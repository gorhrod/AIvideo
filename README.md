# KWJMvideoAI

블로그 데이터나 텍스트로 영상 스토리보드를 자동으로 만들어주는 앱입니다.
채팅으로 아이디어를 구체화하다가 **"🎬 스토리보드로 만들기"** 버튼을 누르면, 로컬에서 실행 중인
LM Studio(Qwen 등)가 장면을 구성하고 바로 편집기로 이동합니다. 사진/영상을 먼저 고르는 방식도
지원합니다 — 미디어 라이브러리나 블로그 가져오기에서 사진·영상을 순서대로 선택하면, 그 선택
그대로 한 장면씩 AI가 나레이션을 붙여 스토리보드를 만듭니다. 완성한 스토리보드는 자막이
실제로 입혀진 MP4로 내보낼 수 있습니다(FFmpeg 사용, SRT/TXT 자막 파일도 함께 생성).

## 사전 준비물 (필수)

1. **[LM Studio](https://lmstudio.ai)** 설치 후, 원하는 모델(기본 설정값: `qwen3.5-9b`, 헤더의
   "설정"에서 변경 가능)을 다운로드해 로드하고, 좌측 **"Local Server"** 탭에서 서버를 시작하세요
   (기본 주소 `http://localhost:1234`). 이 앱은 오직 LM Studio(로컬)만 사용하며 다른 클라우드
   AI는 호출하지 않습니다. **LM Studio가 꺼져 있으면 화면 상단에 빨간 배너로 "연결하기" 안내가
   뜹니다** — 채팅, 스토리보드 자동 생성, AI 재생성 기능은 이 상태에서 동작하지 않습니다.
2. **[FFmpeg](https://ffmpeg.org/download.html)** 설치 후 시스템 PATH에 추가하세요 (자막
   burn-in을 위해 `libass`가 포함된 빌드를 권장합니다 — Windows는 gyan.dev의 "full" 빌드,
   macOS는 Homebrew `brew install ffmpeg`). PATH에 없어도 앱이 macOS/Linux의 흔한 설치 위치를
   자동으로 찾아보며, 그래도 못 찾으면 헤더의 "설정"에서 ffmpeg 실행 파일 경로를 직접 입력할
   수 있습니다.

## 시작하기

```bash
# 의존성 설치
yarn install   # 또는 npm install

# 개발 서버 (핫 리로드)
yarn dev       # 또는 npm run dev

# 프로덕션 실행 (자동으로 build 후 start)
yarn start     # 또는 npm run start
```

> `next start`는 반드시 `next build`로 만든 `.next` 산출물이 있어야 동작합니다.
> 이 프로젝트의 `start` 스크립트는 `next build && next start`로 구성되어 있어
> `yarn start` 한 번으로 빌드부터 실행까지 자동으로 처리됩니다.
> 빌드만 따로 하고 싶다면 `yarn build`, 이미 빌드된 결과로 서버만 켜고 싶다면
> `yarn start:only`를 사용하세요.

브라우저에서 [http://localhost:3000](http://localhost:3000) 을 열어 확인하세요. 화면(헤더 포함)은
항상 브라우저 창 높이에 딱 맞고, 페이지 전체가 스크롤되지 않습니다 — 채팅/편집기 내부만 스크롤됩니다.

## 바로 테스트해보기 (샘플 데이터)

블로그 서버나 실제 사진 없이도 핵심 기능을 바로 써볼 수 있도록 샘플 데이터를 함께 넣어뒀습니다.

- `public/sample-blog-data/` — 제주 가족여행을 소재로 한 블로그 글 3개(사진 5장 + 영상 1개)와
  `posts.json`/`media-meta.json`/`categories.json`/`settings.json`. "블로그에서 가져오기" →
  "블로그 데이터 폴더 연결"에서 이 폴더를 그대로 선택하면 바로 테스트할 수 있습니다.
- `public/sample-media/` — 캡션 없는 사진/영상 파일만 있는 폴더. "미디어 라이브러리" →
  "미디어 폴더 연결"에서 이 폴더를 선택하면, 순수 파일만으로 AI 스토리보드 생성을 테스트할 수 있습니다.

각 폴더 안의 `README.txt`에 자세한 사용법이 있습니다. 앱을 로컬(`yarn dev`)로 직접 실행하는
환경이므로, 폴더 선택 창에서 이 프로젝트 폴더 안의 `public/sample-blog-data` /
`public/sample-media`를 그대로 골라 연결하면 됩니다.

## 주요 기능

- **채팅 화면**: LM Studio와 실시간 스트리밍 대화로 영상 컨셉을 구체화합니다. 준비되면 하단의
  "🎬 스토리보드로 만들기" 버튼을 눌러야 편집기로 이동합니다 (자동 이동 없음).
- **미디어 우선 스토리보드 생성**: 채팅 없이도, 미디어 라이브러리에서 "여러 개 선택해서 AI로
  만들기"로 사진/영상을 순서대로 고르거나, 블로그 가져오기에서 글을 고른 뒤 "AI로 바로
  스토리보드 만들기"를 누르면, 그 미디어 순서 그대로 한 장면씩 나레이션이 붙은 스토리보드가
  즉시 만들어져 편집기로 이동합니다. AI는 사용자가 고른 사진/영상의 개수·순서를 절대 바꾸지
  않습니다.
- **블로그 데이터 가져오기**: "블로그에서 가져오기"로 블로그(`sampledata` 프로젝트)가 만든 데이터
  폴더(`posts.json`/`media-meta.json`/`uploads/`)를 연결하면, 실제 사진·글·캡션을 근거로
  스토리보드를 만듭니다. LLM은 실제로 존재하는 사진/영상만 사용하며, 없는 내용을 지어내지 않습니다.
- **스토리보드 편집기**: 장면 순서 변경/삭제/추가, 제목·나레이션·대사·재생시간·태그 편집,
  "AI 재생성"으로 나레이션을 LM Studio가 다시 작성.
- **비슷한 이미지 추천**: 장면 태그에 따라 어울리는 이미지를 추천하고 클릭 한 번으로 교체.
- **미디어 라이브러리**: 내 컴퓨터의 이미지/영상 폴더를 연결해 실제 로컬 파일을 장면에 바로 적용
  (하나씩 적용하거나, 여러 개를 골라 AI 스토리보드로 한 번에 생성).
- **실제 폴더 저장**: 로컬스토리지·백엔드 없이, 사용자가 지정한 폴더에 채팅 기록·씬 내용·수정 이력을
  실제 파일로 저장(자동저장 + 수동 저장 버튼).
- **프로젝트 관리**: 새 프로젝트 생성(저장 폴더의 `projects/`에 JSON 저장), 저장된 프로젝트 불러오기,
  PDF(인쇄)/JSON/TXT/**MP4**로 내보내기.
- **MP4 내보내기**: FFmpeg으로 장면을 실제 렌더링하고 자막(나레이션+대사)을 영상에 굽습니다.
  화면비율(16:9 가로 / 9:16 세로 — 쇼츠·릴스용), 화질(720p/1080p), 자막 스타일(기본/굵은 화이트/
  옐로우 강조/블랙 박스)을 고를 수 있고, 같은 내용의 **SRT**, **TXT** 자막 파일도 함께
  다운로드됩니다. 장면들은 동시에 병렬로 인코딩되어(코어 수에 따라 최대 4개 동시) 장면이 많은
  프로젝트일수록 순차 인코딩 대비 내보내기 시간이 크게 줄어듭니다.
- **다크모드** 지원.

## AI 응답 속도 최적화

로컬 LLM은 켜져 있는 자체가 아니라 "프롬프트 길이"와 "생성 토큰 제한"에 체감 속도가 크게
좌우됩니다. 이 앱은 다음을 자동으로 적용합니다:

- 대화가 길어져도 최근 메시지 일부만 모델에 전달(오래된 메시지는 자동 생략 — 프롬프트가
  무한정 커지지 않도록).
- 용도별로 적절한 최대 생성 토큰 수(`max_tokens`)를 지정해 모델이 필요 이상으로 길게
  생성하지 않도록 함.
- LM Studio가 아예 응답하지 않는 경우(서버 꺼짐 등)를 빠르게 감지해 무한 로딩 대신 명확한
  오류를 보여줌 (스트리밍 응답은 생성이 길어져도 중간에 끊지 않습니다).

그래도 느리다면, 이는 대부분 로컬 모델 자체의 추론 속도(GPU/VRAM 여부, 모델 크기) 문제입니다 —
더 작은 모델을 쓰거나 LM Studio에서 GPU 오프로드 설정을 확인해보세요.

## 저장 구조 (로컬스토리지·백엔드 없음)

상단 "저장 폴더 연결" 버튼으로 폴더를 선택하면, 그 폴더 안에 `KWJMvideoAI_data/` 폴더가 만들어지고 아래 파일들에 텍스트 데이터가 저장됩니다.

```
[선택한 폴더]/
  README.txt              # 폴더 구조 안내
  KWJMvideoAI_data/
    app_state.json         # 현재 씬 목록, 다크모드 등
    chat_history.json      # 채팅 기록
    edit_log.json          # 수정 이력
    projects/               # "새 프로젝트"로 저장한 프로젝트들
    exports/                # 내보내기 시 함께 저장한 JSON/TXT
```

이미지·영상 원본은 이 폴더에 복사되지 않습니다. "미디어 폴더 연결"로 별도 지정한 폴더의 파일을 참조(파일명 기억)하며, 같은 미디어 폴더를 다시 연결하면 자동으로 미리보기가 복원됩니다.

자세한 설계 배경과 향후 작업 가이드는 프로젝트 루트의 `agent.md`를 참고하세요.

## 폴더 구조

```
app/                    Next.js App Router 엔트리 (layout.tsx, page.tsx, globals.css)
app/api/llm/            LM Studio 프록시 (chat 스트리밍 + 연결 타임아웃, health 체크)
app/api/ffmpeg/check/   FFmpeg 설치 확인 (자동 경로 탐지 포함)
app/api/export/video/   실제 FFmpeg 렌더링(병렬 세그먼트 인코딩) + mp4/srt/txt 다운로드
components/AppRoot.tsx  전체 UI/로직이 담긴 클라이언트 컴포넌트
store/useStore.ts       zustand 전역 상태 (장면, 채팅, 수정이력, 저장/미디어/블로그 폴더 연결, LLM/FFmpeg 설정)
lib/utils.ts            클래스명 병합 유틸(cn), 이미지 자리표시자, 내보내기 해상도 계산 등
lib/fsAccess.ts         File System Access API 래퍼 (실제 폴더 읽기/쓰기)
lib/blogData.ts         블로그 데이터 폴더(posts.json/media-meta.json/uploads) 리더
lib/llm.ts              LM Studio 클라이언트 (스트리밍 채팅, 채팅/미디어 기반 스토리보드 생성, 나레이션 재생성)
lib/subtitles.ts        SRT/TXT 자막 생성 + 자막 가독 시간 기반 최소 재생시간 보정
lib/captionStyles.ts    자막 번인 스타일 프리셋 (기본/굵은 화이트/옐로우 강조/블랙 박스)
lib/server/ffmpeg.ts    서버 전용 ffmpeg 프로세스 실행 유틸 + 자동 경로 탐지 + 동시 인코딩 풀
public/sample-blog-data/  샘플 블로그 데이터 폴더 (바로 테스트용)
public/sample-media/      샘플 미디어 폴더 (바로 테스트용)
agent.md                AI 코딩 어시스턴트용 프로젝트 가이드 (변경 시 함께 업데이트)
```
